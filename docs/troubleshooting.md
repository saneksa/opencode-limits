## Симптом → причина → действие

| Симптом | Причина | Действие |
| --- | --- | --- |
| Баннер «Недействительный ключ API OpenCode Go (401)» | Ключ отсутствует, устарел или указан неверно | В «Настройках» → «Ключ доступа Go» сохранить актуальный ключ через «Сохранить в Keychain» либо задать `OPENCODE_GO_KEY=<ключ>`; нажать «Проверить соединение» |
| «Подписка OpenCode Go отсутствует или не активна: …» (403) | Ключ действителен, но у аккаунта нет активной подписки Go | Проверить статус подписки в аккаунте OpenCode; смена ключа не поможет |
| «Ошибка сети: …», лимиты не обновляются | Нет сети, либо системный HTTPS-прокси недоступен | Проверить соединение; прокси задан через `scutil --proxy` (127.0.0.1:1082), а не переменными окружения. `curl` вручную нужно вызывать с `-x`, `URLSession` использует `SystemConfiguration` |
| Пустое окно «Активность» | Нет событий за выбранный период, неверный путь к БД, либо OpenCode Desktop не запускался | Проверить `OPENCODE_DB_PATH`, убедиться, что OpenCode Desktop запускался, и выбрать период «Всё время» — история может быть за прошлые месяцы |
| Подпись «Источник: Локальная БД» вместо «API OpenCode» | Локальный OpenCode V2 API недоступен (не запущен Desktop, нет пароля из конфигурации, таймаут/ошибка разбора), сработал fallback к SQLite | Это ожидаемое поведение: данные берутся из БД только для чтения. Запустить OpenCode Desktop и повторить «Обновить» |
| `/api/experimental/usage/limits` отвечает `data: null` | Сервер не вернул полезную нагрузку для лимитов | Данные лимитов берутся из `GET /inference/go/v1/usage`; пустой `data` у experimental-эндпоинта не является ошибкой приложения. Повторить обновление позже |
| Иконка не меняется | Показан кэшированный снимок; выбран другой источник иконки; приложение не опрашивало сеть | Открыть окно, нажать «Обновить», проверить настройку «В строке меню»; смена настроек «В строке меню» и «Кольцо отката 5 ч» перерисовывает иконку мгновенно, без запроса |
| Нижние разделы настроек обрезаны, длинные подписи с «…» | Старый размер окна и непереносимые подписи | Окно теперь 480×640, масштабируемое (440×420 … 760×1100) и прокручиваемое; при необходимости растянуть его мышью |
| При `make run` уведомления заменяются звуковым сигналом | У бинарника из SwiftPM нет bundle identifier | Это ожидаемо: `NSSound.beep()` используется, когда нет разрешения или `Bundle.main.bundleIdentifier == nil`. Для настоящих уведомлений собрать `.app` через `make app` / `make install` |
| `swift test` падает с `unable to resolve module dependency: 'XCTest'` | В CommandLineTools нет `XCTest.framework`, тесты не используют XCTest | Выполнить `make test` (или `make smoke` для живых проверок) |
| Ошибка макроса `external macro implementation type 'SwiftUIMacros.StateMacro' could not be found` | В CommandLineTools отсутствует плагин `SwiftUIMacros` | Не использовать `@State`, `@AppStorage`, `#Preview`, `@Observable`, `@Environment(\.openSettings)`; применять `@StateObject`, `ObservableObject`, `Binding` |
| `sqlite3.h not found` | Заголовок есть только в sysroot SDK | Использовать таргет-заглушку `CSQLite3`; правка путей не требуется |
| «Не удалось изменить автозапуск…» | `SMAppService` требует настоящий `.app` | Собрать `make app`, установить через `make install` и включить тумблер снова |
| Опасения по поводу сна Mac | Приложение не создаёт power-утверждений | `IOPMAssertion`, `beginActivity` и `caffeinate` не используются; на `willSleepNotification` таймеры и текущий запрос останавливаются, на `didWakeNotification` — возобновляются |
| После `make install` открылась старая версия | Процесс предыдущей версии ещё жив | `killall OpenCodeLimits`, затем `make install` и заново открыть приложение |

## Как собрать диагностику

Команды ниже **не печатают ключ и заголовки запросов**:

```sh
swift build -c release
make test
make smoke                 # только при необходимости проверить живые API/БД
scutil --proxy             # проверить системный прокси (без секретов)
plutil -lint build/OpenCodeLimits.app/Contents/Info.plist
codesign -v build/OpenCodeLimits.app
git status --short
git check-ignore -v .build build
```

Полезно приложить: версию macOS (`sw_vers`), вывод `swift --version`, текст ошибки из баннера окна и выбранный период/метрику окна «Активность».

**Перед отправкой логов обязательно замените все ключи, токены и пути с именем пользователя подставными значениями** (например, `<ключ>`, `<путь-к-БД>`). Если для проверки использовался `OPENCODE_GO_KEY`, не копируйте его значение в отчёт.
