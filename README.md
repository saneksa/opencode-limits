# OpenCode Limits

Десктопное приложение для macOS, которое живёт в строке меню и показывает расход
подписки **OpenCode Go**: три лимита (5 часов, неделя, месяц), время до их сброса
и историю активности. Написано на SwiftUI, без внешних зависимостей и без Xcode —
достаточно Command Line Tools.

```bash
make build && make install && open /Applications/OpenCodeLimits.app
```

Подробная документация — в [`docs/`](docs/README.md): архитектура, источники
данных, настройки, интерфейс, сборка и тесты, безопасность, диагностика.

---

## Возможности

- Три карточки лимитов Go с процентом, статусом и живым отсчётом до сброса.
- Иконка в трее с **одним зелёным кольцом** — временем до отката 5-часового лимита.
- **Правый клик** по иконке — меню «Открыть / Настройки… / Выход»; левый клик — окно с лимитами.
- Экран активности: график по дням или месяцам, токены и стоимость, последние сессии, топ моделей.
- Уведомления macOS при достижении порога (один раз на окно).
- Энергосбережение: реже опрашивает API на батарее и в Low Power Mode, не мешает засыпать ноутбуку.

## Лимиты OpenCode Go

Приложение опрашивает официальный API подписки:

```
GET https://opencode.ai/inference/go/v1/usage
Authorization: Bearer <ключ>
User-Agent: opencode-limits-monitor/0.1
```

| Окно | Что означает | Когда сбрасывается |
| --- | --- | --- |
| `rolling` | «5 часов» — 20 % месячного лимита | Через 5 часов после первого использования в окне; до начала окна время сброса — сейчас + 5 часов |
| `weekly` | «Неделя» — 50 % месячного лимита | Каждый понедельник в 00:00 UTC |
| `monthly` | «Месяц» — весь лимит периода | В начале оплаченного периода |

Для каждого окна показывается процент, статус (`ok` или `rate-limited`) и отсчёт
до сброса. Если лимит исчерпан или достигнут порог предупреждения (по умолчанию
80 %, настраивается), карточка и иконка подсвечиваются; при переходе порога
приходит уведомление macOS.

## Иконка в строке меню

Иконка рисуется программно и содержит **одно внешнее кольцо**:

- **Зелёная убывающая дуга** — сколько осталось до сброса 5-часового окна:
  полное кольцо = все 5 часов впереди, пустое = сброс сейчас. Обновляется раз в
  30 секунд без сетевого запроса. Красная только когда выбранный лимит исчерпан.
- **Цифра в центре** — процент выбранного лимита: 5 часов / Неделя / Месяц /
  Авто (наибольший процент, при исчерпании — окно со статусом `rate-limited`).
  По умолчанию показываются 5 часов.

Три карточки в окне и уведомления всегда показывают все три лимита — выбор
метра влияет только на цифру в иконке.

**Управление:** левый клик открывает окно с лимитами и активностью, правый клик
показывает меню с пунктами «Открыть», «Настройки…» и «Выход». Приложение
объявлено как `LSUIElement`, поэтому не имеет иконки в Dock.

## Активность

По умолчанию данные берутся из **локального API OpenCode Desktop (V2)**:
`GET /api/experimental/session/stats` и `GET /api/session`. Оттуда приходят
агрегаты по дням, токены, стоимость, модели, число шагов, сессии, активные дни
и серия. Если сервис не запущен, нет пароля или запрос не удался — приложение
молча переключается на локальную SQLite-БД; использованный источник
(«API OpenCode» или «Локальная БД») виден в интерфейсе.

Доступны период **7 / 30 / 90 дней / «Всё время»** (для конечных периодов график
по дням, для «Всё время» — по месяцам), переключатель метрики «Токены / $»,
сводные плитки, последние 12 сессий и топ моделей. На бесплатных моделях
стоимость равна нулю, поэтому токены — основная метрика.

### Откуда берутся данные

| Данные | Источник |
| --- | --- |
| Лимиты Go | напрямую `https://opencode.ai/inference/go/v1/usage` |
| Активность | локальный V2 API `http://127.0.0.1:<порт>` → при недоступности SQLite |
| Ключ Go | `~/.local/share/opencode/opencode.db`, `OPENCODE_GO_KEY` или Keychain |
| Пароль локального API | `~/.config/opencode/service.json` |

Порт локального сервиса узнаётся командой `opencode-cli service status`,
авторизация — `Basic base64("opencode:" + password)`. Запросы к `opencode.ai`
идут через системный HTTPS-прокси (`SystemConfiguration`, fallback `HTTPS_PROXY`),
запросы к localhost — в обход прокси. Эндпоинт
`/api/experimental/usage/limits` на этой машине возвращает `data: null`, поэтому
лимиты берутся напрямую у Go, а не через локальный сервис.

## Источники ключа API

Ключ Go (`oc_sk_…`) ищется в таком порядке (источник по умолчанию — локальная
база; порядок меняется в настройках):

1. **opencode.db** — таблица `credential`, строка `integration_id =
   'opencode-go' AND active = 1`, JSON-поле `key`. Путь по умолчанию
   `~/.local/share/opencode/opencode.db`, переопределяется `OPENCODE_DB_PATH`.
2. **OPENCODE_GO_KEY** — переменная окружения.
3. **Keychain** — ключ, введённый вручную в настройках (сервис
   `dev.alex.opencodelimits`, аккаунт `go-api-key`).

Если выбранный первым источник пуст, приложение пробует остальные. Ключ читается
заново при каждом опросе.

## Настройки

Окно настроек 600×700, растягиваемое, с прокруткой и тремя вкладками
(сегментированный `Picker`; выбор вкладки не сохраняется):

| Вкладка | Что внутри |
| --- | --- |
| **Общие** | Интервал опроса (30 сек / 1 мин / 5 мин), «В строке меню» (`TrayMeter`), общая подпись «Кольцо показывает время до сброса 5-часового окна, цифра — выбранный лимит. В окне и в уведомлениях всегда видны все три лимита.», порог предупреждений (0…100, шаг 5), запуск при входе в систему |
| **Подключение** | Источник ключа, «Активный источник: …», новый ключ, «Сохранить в Keychain» / «Удалить», «Проверить соединение» с результатом |
| **Энергосбережение** | «Уменьшать опрос от батареи», интервал от батареи (1/5/15 мин), подпись о питании и текущем интервале, подсказка про Low Power Mode / батарею / сон |

Снизу окна, вне области прокрутки, постоянно видна строка:
«Ключ не логируется · БД только для чтения · содержимое переписки не читается».

## Энергосбережение и сон

Состояние питания определяется через Low Power Mode и `pmset -g batt` (результат
кешируется на 60 секунд). С включённым тумблером «Энергосбережение» на батарее
или в Low Power Mode:

| | Обычно | Энергосбережение |
| --- | --- | --- |
| Опрос лимитов | 60 с | не чаще 5 мин (настраивается 1 / 5 / 15 мин) |
| Перерисовка иконки | 30 с | 60 с |
| Обновление активности | 5 мин | 15 мин |

Таймеры приостанавливаются по `NSWorkspace.willSleepNotification` и при
пробуждении сразу обновляют данные. **Приложение не мешает засыпать ноутбуку**:
в коде нет `IOPMAssertion`, `beginActivity`, `caffeinate` и background-сессий,
поэтому Mac засыпает по отсутствию пользовательского ввода как обычно.

## Сборка и установка

Нужны macOS 13 или новее и SwiftPM (Xcode Command Line Tools). Внешних пакетов нет.

```bash
make build    # swift build -c release
make test     # 178 проверок, dependency-free test runner
make smoke    # то же + живой запрос к Go API и чтение реальной БД / локального API
make run      # отладочный запуск приложения
make app      # собрать build/OpenCodeLimits.app и подписать ad-hoc
make icon     # пересобрать иконку приложения (PNG + ICNS)
make install  # скопировать приложение в /Applications
make clean    # swift package clean
```

### Иконка приложения

[`Resources/AppIcon.icns`](Resources/AppIcon.icns) задаётся ключом
`CFBundleIconFile` в `Info.plist` и копируется в `Contents/Resources/` целью
`make app` **до** подписи. Это тёмный скруглённый квадрат с зелёными песочными
часами — символом времени до сброса 5-часового окна; без колец, без синего и без
текста. Исходник рисуется кодом:
[`scripts/generate-appicon.swift`](scripts/generate-appicon.swift) создаёт
1024×1024 PNG и все 10 размеров `.icns` через `sips` + `iconutil`. Правки дизайна —
в этот скрипт, затем `make icon && make app`.

Иконка в строке меню рисуется отдельно и «живая» — см.
[`docs/ui.md`](docs/ui.md).

Готовый бандл: `open build/OpenCodeLimits.app`. Для отладки
`OPENCODE_SHOW_SETTINGS_ON_LAUNCH=1` открывает окно настроек сразу при старте.
При запуске через `make run` бинарник работает без `.app`-бандла, поэтому
системные уведомления недоступны — вместо них звуковой сигнал; в установленном
приложении уведомления работают.

Запуск при входе (Launch at Login) требует установленного `.app` в
`/Applications` — это делает `make install`.

### CI

[`.github/workflows/build.yml`](.github/workflows/build.yml) собирает приложение
на macOS-раннере GitHub Actions: `make test` → `make app` → ZIP-артефакт. Тег `v*`
автоматически создаёт GitHub Release. `make smoke` в CI не запускается — ему нужны
ключ Go и локальный сервис OpenCode Desktop. Подробности — в
[`docs/build-and-test.md`](docs/build-and-test.md).

### Особенности окружения

На машине только CommandLineTools, поэтому:

- `XCTest.framework` отсутствует → тесты сделаны отдельным executable-таргетом
  `OpenCodeLimitsTests` с собственным раннером (`check` / `equal`, вывод
  `[PASS]` / `[FAIL]`, ненулевой код при провале). `swift test` не используется.
- Плагин `SwiftUIMacros` отсутствует → UI не использует `@State`, `#Preview`
  и `@Environment(\.openSettings)`; состояние на `@StateObject` / `ObservableObject`,
  окно настроек через `NSHostingController`.
- Заголовок `sqlite3.h` лежит только в SDK → системный модуль `CSQLite3` через shim.
- Файл точки входа называется `OpenCodeLimitsApp.swift`, **не** `main.swift`: SwiftPM
  считает `main.swift` модулем с top-level code и запрещает в нём `@main`
  (ошибка проявляется на чистой сборке, например в GitHub Actions).
- Приложение стартует через **чистый AppKit** (`@main enum Main` →
  `NSApplication.shared.run()` → явный `AppDelegate.bootstrap()`), без SwiftUI
  `App`/Scene. Иначе единственная `SwiftUI.Settings` сцена сама открывала окно
  настроек при первом запуске. Все окна создаются вручную; при обычном старте
  окон нет вообще.

## Безопасность и приватность

- **В репозиторий не попадают ключи.** Ключ Go, пароль локального сервиса и БД
  хранятся вне проекта (`~/.local/share/opencode/`, `~/.config/opencode/`,
  Keychain). Сканирование исходников не нашло реальных ключей, токенов или
  base64-паролей — только шаблоны вида `oc_sk_…` в документации и тестах.
- `.gitignore` исключает `.build/` (артефакты SwiftPM), `build/` (собранный
  `.app`), `*.log`, `.env*`, `.DS_Store` и временные файлы редакторов.
- Ключ не записывается в логи, файлы или `UserDefaults`; в Keychain попадает
  только ключ, введённый вручную. Пароль локального API читается из
  `service.json` на каждый запрос и не логируется.
- База OpenCode открывается **только для чтения** (`SQLITE_OPEN_READONLY`).
  Текст сообщений (`data.content`) не читается, устаревшая таблица `part` не
  используется — она дублирует `session_message` и удвоила бы суммы.
- Сетевые запросы идут только на `opencode.ai` и на `127.0.0.1` (локальный
  сервис OpenCode). Никаких других адресов приложение не знает.

## Диагностика

| Симптом | Что сделать |
| --- | --- |
| 401 «Недействительный ключ API» | Проверьте активную запись в `opencode.db`, `OPENCODE_GO_KEY` или введите новый ключ в настройках |
| 403 «Подписка отсутствует» | Для аккаунта нет действующей подписки Go; приложение покажет сообщение сервера |
| Нет соединения | Проверьте сеть и системный HTTPS-прокси; настройки перечитываются при каждом опросе, нажмите «Обновить». Быстрая проверка — `make smoke` (секреты не выводятся) |
| Пустая активность | Проверьте `OPENCODE_DB_PATH`, запущен ли OpenCode Desktop, переключите период на «Всё время» |
| Иконка не обновилась | Откройте окно (левый клик) или нажмите «Обновить»; смените источник в настройках |
| Окно настроек обрезано | Окно растягивается; вкладки компактные и помещаются целиком, потяните за край |
